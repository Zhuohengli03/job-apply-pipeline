# 选岗与匹配度判断

## 一、发布时间
- **聚合招聘平台**（LinkedIn、Indeed、Handshake、BOSS 直聘、猎聘、实习僧）：优先 24 小时内发布；不够再往前，最长 2 周（BOSS 这类看不到发布时间的，用“HR 今日/3 日内/本周活跃”代替，最长 3 周）。超过就不投。尽量用平台自带的时间筛选。备注写发布时间，看不到写“发布时间未知”。
- **公司官网 / 校招官网 / Greenhouse・Ashby・Lever 招聘页**：不看发布时间，岗位开放、在截止日前就能投。备注写截止日期（没写的写“截止日期未知”）。

## 二、三道硬关（任何一道不过就不投）
1. **担保**：用户需要担保时，JD 写明“不提供签证担保 / 必须是公民或绿卡 / 不接受 OPT”的不投。表单里问“是否需要担保”的照实答，照样提交（会不会被筛掉由对方决定）。
2. **年限**：超过档案里的上限（常见是“要求 3 年以上不投”）不投；应届/Associate/New Grad 优先，不够再投 1–2 年。
3. **硬门槛**：学历/专业硬性要求（如“STEM 本科”“985/211”“理工科”）、必需语言、必需技能/证书（如 UE5）、必需作品、必需的特定游戏经历（如“深度体验过 3 款二次元手游”“重度 SLG 玩家”）——用户不满足就不投。

## 三、逐条对照 JD（防止“关键词一样就算对口”）
把 JD 的职责和要求逐条列出，每条标三档：
- **直接做过**：简历里有同类任务、同类指标。
- **可迁移**：做过相关的事，但场景或规模不同。例：自己个人项目的注册→创作漏斗 ≠ 做过 C 端增长链路；自己发过邀请码 ≠ 做过分享裂变；没有推荐系统、push、投放经验就别说对口。
- **没有**。

判断：
- 核心职责（通常是前 3 条）里至少一半“直接做过” → **匹配**。
- 全是“可迁移” → **勉强**：只能在不限投渠道试投，备注写“勉强，缺口：…”。
- “优先”条件一条都没有 → 降一档。
- 每个岗位都写“匹配点”一句、“缺口”一句，不能只写“对口”。

## 四、限投平台
- 有名额上限的（如某些大厂校招每人 1–5 个志愿、方向投后不可更换、全渠道 N 次、30 天内最多 N 个职位、集团内同时只考虑一个岗位）：只推荐达到“匹配”的岗位；都不达标就直接说“没有合适的，建议名额先留着”。
- 列 2–3 个候选给用户选（链接、匹配点、缺口），并保留岗位页标签。
- 用户决定后再投；投完把“已用名额”更新进档案。
- 一份在线简历挂多个志愿时算性价比：选能同时打满名额的那份简历；投完不要再改该官网的在线简历。

## 五、一般不投
- 博彩/iGaming、纯销售、客服、陪玩、直播带货；要先轮岗半年以上销售的管培。
- 培训贷，或无名小公司开异常高薪。
- 外包合同工（时薪制）——除非用户说可以。
- 只有手机 App 才能投的。
- 用户在档案里列出“自己处理”的公司。

## 六、匹配写法示例
> 匹配点：JD 核心是“用户访谈+指标驱动迭代”，对应个人项目里读完 119 份用户申请归成 10 类需求、搭五步漏斗定位流失环节。缺口：没有正式 PM 年限，没有保险理赔行业经验。
