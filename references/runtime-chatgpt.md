# 在 ChatGPT 里运行

适用：ChatGPT 的 Skills（工作区管理员要先开启）、Projects / 自定义 GPT、agent 模式、ChatGPT Atlas 浏览器、代码解释器（数据分析）。各功能是否可用取决于用户的套餐和设置——第一次运行时先确认手上有哪些能力，再按下表选做法。

## 能力对照
| 需要做的事 | ChatGPT 里的做法 | 做不到时的降级 |
|---|---|---|
| 操作网页填表 | **agent 模式**（在云端虚拟浏览器里操作），或 **Atlas 浏览器的 agent**（在用户自己的浏览器里操作，可沿用已登录状态） | 逐题给出要填的答案，用户自己贴 |
| 拿到简历/投递表 | 用户把简历 PDF、`profile.md`、投递表 xlsx 上传到对话或 Project 文件里 | 让用户上传 |
| 上传简历到网页 | agent 模式里用对话中已上传的文件；Atlas 在用户本机浏览器里选文件 | 告诉用户“这一栏请你自己选 xxx.pdf”，然后由你核对页面显示的文件名 |
| 跑 Python（CL 生成、Excel 更新） | 代码解释器：运行 `scripts/` 里的脚本（把脚本内容贴进去执行，或随 skill 一起提供） | CL 直接写正文；Excel 给出要粘贴的整行 |
| 改用户电脑上的 Excel | 不能直接改本机文件：在代码解释器里改上传的那份，生成新 xlsx 让用户下载覆盖 | 给出整行文本 |
| 查回信 | Gmail 等连接器（Apps），或 agent 打开网页邮箱 | 让用户告诉你收到了什么 |
| 每日自动运行 | ChatGPT 的定时任务（Tasks）只适合提醒和汇总；真正填表需要 agent，按用户手动触发为准 | 每天由用户说一句“开始今天的投递” |

## agent 模式要注意
- **登录**：agent 的云端浏览器默认没有用户的登录状态。遇到登录页，请用户点“接管（Take over）”自己登录，再交还；绝不让用户把密码发在聊天里，也不代输。
- **确认**：agent 在提交表单等关键操作前会请求确认——这和本 skill 的规则一致：同意类勾选、验证码、证件号都交给用户。
- **会话结束页面就没了**：停在需要用户处理的那一步时，把“公司｜职位｜申请链接｜停在哪一步｜用户要做什么”写进汇总，用户之后自己打开链接接着做。
- **不能执行页面 JS**：`platform-playbook.md` 里的 JS 技巧（native setter、拦截 click、读 shadow DOM）用不了，改用点击、键入、键盘（Tab/方向键/Enter），每一步看截图核对。React 下拉一般“点开 → 键入 → 选项”可行。
- **上传核对**：上传后看页面上显示的文件名；能预览的点开预览看第一行是不是用户姓名、是简历不是信。
- 速度比本地浏览器慢，一次运行先投少量（如 3–5 份），稳定后再加量。

## Atlas 浏览器
- 在用户本机运行、能用已登录的网站，体验最接近 Claude in Chrome。需要本人操作的页面留着标签即可。
- 同样遵守：密码、验证码、同意项、证件号由用户本人操作。

## 文件与笔记
- 建议用户建一个 ChatGPT Project「求职」，把 `profile.md`、各版简历 PDF、投递表 xlsx、每日踩坑笔记放进项目文件；每次更新投递表后，提醒用户用新下载的 xlsx 替换项目里的旧版（否则下次查重会漏）。
- 生成的 cover letter PDF 提供下载，提醒用户存进自己的 Cover Letters 文件夹。
